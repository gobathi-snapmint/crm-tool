1. Executive Vision & Core Mindmap

Snapmint manages high-velocity communications across WhatsApp, SMS, and Push to drive repeat BNPL purchases, personal loans, and timely repayments. Today, running a single campaign requires 24 to 48 hours of manual turnaround across Vilpower DLT, Route Mobile, WebEngage, and Databricks.

This platform creates ONE Central CRM Campaign Calendar Portal. A marketer inputs a brief, and specialized AI agents collaborate to generate localized copy, render brand graphics, verify DLT/WhatsApp compliance, and assemble WebEngage execution packages.

HUMAN-ONLY LAUNCH GATE: AI agents never launch campaigns autonomously. The platform enforces 4 separate permissions (generate content, submit templates, create drafts, launch). Final launch authority is strictly reserved for authorized human campaign managers.

2. End-to-End Hop-by-Hop Request Flow

The exact journey of every campaign request from client submission to final launch:

  • Hop 1 (Client to Backend): React Portal on S3/CloudFront issues HTTPS POST request to FastAPI backend on AWS ECS Fargate in Mumbai VPC.
  • Hop 2 (Backend to Database RAG): FastAPI queries Aurora PostgreSQL over private VPC endpoints to fetch 2-3 approved golden past templates for the product line.
  • Hop 3 (Backend to Bedrock Mumbai): FastAPI invokes AWS Bedrock using India Geographic Inference Profile (in.anthropic.claude-sonnet-5). Compute routes between Mumbai (ap-south-1) and Hyderabad (ap-south-2) with Zero Data Retention (ZDR), returning structured JSON copy and Layout spec.
  • Hop 4 (Backend to Chromium): Passes Layout JSON to Headless Chromium container in Mumbai VPC. Renders 1080x1080 PNG in <400ms.
  • Hop 5 (Renderer to S3): Stores PNG buffer in private S3 bucket with KMS CMK encryption; returns expiring pre-signed URL.
  • Hop 6 (WhatsApp Submission): Submits template payload to Route Mobile via POST /wba/template/create (Bearer JWT). Listens to Meta status webhooks for real-time approval updates.
  • Hop 7 (SMS DLT Whitelist Check): Computes SHA-256 hash of SMS copy and checks local Aurora DLT Whitelist Ledger (manually seeded with Vilpower approved IDs). If matched, marks DLT Whitelisted (Green). If new, outputs One-Click Vilpower Package for operator to submit with POC OTP.
  • Hop 8 (WebEngage Spec): Formats Guided Execution Spec. Marketer copies to WebEngage. Portal reads back draft and runs SHA-256 diff.
  • Hop 9 (Human Launch Gate): Authorized campaign manager inspects unified pre-flight QA report and clicks final Launch button.

3. Master Feasibility Scorecard: What is Possible vs. Not Possible

Subsystem Target Capability Feasibility Status Technical Reality & Solution
AWS Bedrock Mumbai Claude Sonnet 5, Opus 5, Haiku 4.5, GPT-5.6 Terra HIGH FEASIBILITY Supported via India Geographic Profiles routing between Mumbai (ap-south-1) and Hyderabad (ap-south-2). Zero Data Retention, RBI/DPDP compliant.
AI Image Generation Stable Diffusion 3.5 / Nova Canvas in India NOT POSSIBLE IN INDIA No production image models exist in Indian AWS data centers. Solved via Headless Chromium in Mumbai VPC (<400ms PNG rendering).
WhatsApp BSP Template API Route Mobile / Infobip programmatic creation HIGH FEASIBILITY Route Mobile endpoint POST /wba/template/create (Bearer JWT auth) submits templates directly to Meta.
WhatsApp Real-Time Status Real-time category check & status tracking HIGH FEASIBILITY Meta webhook message_template_status_update pushes status changes (APPROVED, REJECTED, CATEGORY_CHANGED) to portal via Server-Sent Events (SSE).
Telecom DLT SMS API Automated SMS approval via direct telco API NOT POSSIBLE (TRAI MANDATE) TRAI mandates manual web portal login with SMS OTP sent to company POC + CAPTCHA. Solved via Portal Whitelist Ledger + manual POC entry.
WebEngage Campaign Drafting Programmatic draft creation from scratch NOT POSSIBLE (PUBLIC API) Public REST API only triggers running campaigns. Solved via Guided Execution Package + One-Click copy + read-back diff.
Databricks Analytics Read-only SQL metrics integration HIGH FEASIBILITY Direct connection to Databricks SQL Warehouse via PrivateLink. Pulls 100% deterministic numbers.

4. The End-to-End Agent Ecosystem (Agents 01 through 08)

Agent Underlying Technology Operational Role
Agent 01: Content & Copy Claude Sonnet 5 (Mumbai ap-south-1) Generates 3 copy variants (EN, HI, Hinglish) with strict character bounds and UTM tags.
Agent 02: Creative Engine Headless Chromium in Mumbai VPC Renders Layout JSON into pixel-perfect 1080x1080 PNG banners in <400ms. Claude Vision QA checks contrast.
Agent 03: WhatsApp Approval Dual-Model Consensus (Sonnet 5 + GPT-5.6) Submits templates via Route Mobile / Infobip API and tracks real-time approval webhooks.
Agent 04: SMS / DLT Compliance Claude Haiku 4.5 + SHA-256 Hashing Matches text against pre-approved Vilpower DLT templates and calculates GSM-7 vs UCS-2 character credits.
Agent 05: WebEngage Draft Claude Sonnet 5 Builds Guided Execution Specification and executes deterministic read-back diff to catch copy-paste mismatches.
Agent 06: Debugging Agent Claude Sonnet 5 Analyzes vendor API error payloads (e.g. invalid phone, quota limits) and recommends corrective fixes.
Agent 07: Analytics & Attribution Claude Sonnet 5 + Databricks SQL Reads deterministic Lakehouse conversion metrics and auto-seeds top 10% campaigns into the content library.
Agent 08: Calendar Planning Claude Opus 5 + OR Constraint Solver Proposes monthly schedules balancing customer frequency caps (max 2 WhatsApp/wk) and channel budgets.
