1. The Complete Plan: Phase-by-Phase Roadmap

The goal of this initiative is to replace manual copy-pasting across four disconnected dashboards (Vilpower DLT, WhatsApp BSPs, WebEngage, and Databricks) with ONE Central CRM Campaign Calendar Portal. The roadmap is structured into 6 clear, sequential phases:

Phase Focus Area Timeline What Gets Delivered
Phase 0 Foundations & Spikes Weeks 0 – 4 Golden evaluation dataset (50-100 historical campaigns), AWS Bedrock Mumbai setup, and vendor API discovery spikes.
Phase 1 The Portal & Content Engine Weeks 4 – 10 Working Campaign Calendar Portal, brief ingestion with custom comments, connection to Bedrock Mumbai, and headless PNG banner rendering.
Phase 2 WhatsApp & SMS Automation Weeks 10 – 24 Direct Route Mobile / Infobip API template submission, dual-model consensus (utility vs marketing), and SHA-256 DLT text matching.
Phase 3 Multi-Language & Debugging Weeks 20 – 34 Deep Hinglish and Hindi localization, Push notification support, and automated API error diagnostic agent.
Phase 4 Databricks Lakehouse Loop Weeks 30 – 40 Read-only SQL connection to Databricks; deterministic delivery & GMV reporting; auto-seeding top 10% campaigns into library.
Phase 5 Calendar Planning Agent Weeks 38 – 52 Claude Opus 5 + constraint solver recommending optimal monthly schedules based on customer fatigue and frequency caps.
The Non-Negotiable Hard Rule: AI agents never get autonomous campaign launch permissions in any phase. A human campaign manager must review the unified pre-flight QA report and click the final launch button.

2. Phase 1 Deep-Dive: Building the Portal

In Phase 1, we build the core interface that the CRM team will use daily. Instead of writing copy in Google Docs or spreadsheets, the marketer fills out a guided 1-minute brief.

Portal Input Fields Specification

  • 1. Product Line (Dropdown): Selects the active Snapmint offering (0% EMI BNPL Mobiles/Electronics, Personal Loan / Cash on EMI, Merchant Partner Flash Deals, EMI Repayment Reminders).
  • 2. Audience Segment & Trigger Event (Dropdown): The segment dropdown encodes both the user profile and the behavioral trigger event performed by the customer:
    • Cart Abandoner: User added product to cart and completed OTP, but dropped off at payment.
    • Approved Zero Utilization: Granted credit limit (e.g. ₹15,000) but inactive for 14 days.
    • Repeat Limit Upgrade: Paid 2+ EMIs on time; eligible for limit upgrade to ₹40,000.
    • Dormant 90 Days: Past customer with no transaction in 90+ days.
    • Near-Due 48 Hours: Installment due in 48 hours; repayment link.
  • 3. Communication Channel (Radio / Selector): WhatsApp Business message, SMS, or Mobile Push Notification.
  • 4. Target CTA URL (Input Field): Base destination link (e.g., https://snapmint.com/merchant/oneplus). The portal deterministically appends standard UTM parameters.
  • 5. Custom Comments / Special Instructions Box (Multi-line Textarea): This satisfies your requirement for custom marketer guidance. The marketer can type specific nuances such as:
    "Highlight flat ₹500 instant cashback on Axis Bank cards."
    "Keep tone very urgent: festive flash deal ends tonight at 12 midnight."
    "Mention zero paperwork and 2-minute bank disbursement."

3. How the Portal Connects to AWS Bedrock in Mumbai

The architecture ensures 100% in-country data residency and sub-5-second response times:

  1. Frontend Submission: React portal sends the JSON brief to our FastAPI backend running on AWS ECS Fargate inside a private Mumbai VPC.
  2. Context Enrichment: The backend queries our local database (Aurora PostgreSQL) to retrieve 2–3 pre-approved high-converting past campaign examples for that exact product line.
  3. Prompt Assembly: The backend merges the Product Rules + Customer Segment + Trigger Event + Golden Examples + the Marketer's Custom Comments into a structured system prompt.
  4. Bedrock API Call: Backend calls AWS Bedrock in Mumbai using boto3 targeting the India Geographic Inference Profile (in.anthropic.claude-sonnet-5). Compute dynamically routes between Mumbai (ap-south-1) and Hyderabad (ap-south-2) with Zero Data Retention (ZDR).
  5. Deterministic Post-Processing: Python code validates that character counts meet channel bounds (160 chars for SMS GSM-7), validates URLs, and sends the layout spec to our headless Chromium service to render the banner graphic to PNG in <400ms.
  6. Unified Review Screen: Returns the complete bundle to the portal in 2–4 seconds for marketer review.

4. Model Training Feasibility: Should We Train on Old Datasets?

A key question is whether we should fine-tune a model on Snapmint's historical campaign datasets across product lines and segments. Here is the honest technical evaluation:

Evaluation Dimension Fine-Tuning a Custom Model In-Context RAG + Bedrock Prompt Injection (Recommended)
Mumbai Data Residency RESTRICTED: Claude fine-tuning is only available in US regions (`us-east-1`/`us-west-2`), which violates in-country data residency. (Only Amazon Nova/Titan supports fine-tuning in Mumbai). 100% COMPLIANT: Claude Sonnet 5 on India Geographic Profile operates entirely inside Mumbai & Hyderabad data centers.
Cost & Infrastructure HIGH: Requires purchasing Bedrock Provisioned Throughput (committed GPU hours costing thousands of dollars/month). NEAR ZERO: On-demand pay-per-token inference costing less than ₹2 per campaign brief.
Flexibility to Policy Changes BRITTLE: If EMI rates, brand taglines, or Meta WhatsApp policies change, the fine-tuned model requires a full retraining cycle. INSTANT: Updating system instructions or adding custom comments takes effect immediately without retraining.
Quality on Copywriting Moderate (risk of repetitive outputs and catastrophic forgetting). SUPERIOR (95%+): Pre-trained frontier model (Sonnet 5) with 3 past winning examples writes exceptional copy.
Feasibility Verdict: Do NOT fine-tune in Phase 1. Using Claude Sonnet 5 with In-Context RAG (prompt injection of golden examples + marketer custom comments) delivers 95%+ brand accuracy on Day 1 with zero training cost and complete data residency in Mumbai.

5. If We DO Want to Train in Mumbai: How to Execute It

If leadership decides to train an in-region model (such as Amazon Nova Pro, which supports native Supervised Fine-Tuning in Mumbai), here is the exact technical blueprint:

A. Required Data Sources

  • Databricks Lakehouse: Query historical campaigns joined with Click-Through Rates (CTR > 3%) and 30-day BNPL conversion rates.
  • WebEngage Campaign Archive: Past WhatsApp copies, SMS dispatches, and push notifications.
  • Vilpower DLT Database: Approved telecom SMS templates with {#var#} variables.

B. Data Volume Needed

A minimum of 2,500 curated prompt-completion pairs (ideally 5,000 pairs) covering 0% EMI checkout, Personal Loan cash withdrawals, partner brand deals, and repayment alerts.

C. Required Data Format (Bedrock JSONL)

{"system": "You are the Snapmint CRM Specialist Agent. Generate compliant, high-converting copy.", "messages": [{"role": "user", "content": "{\"product_line\":\"0% EMI BNPL Checkout\",\"segment\":\"High-Intent Cart Abandoner\",\"user_context\":{\"product\":\"Smart TV\",\"cart_value\":\"₹24,999\",\"downpayment\":\"₹0\",\"emi\":\"₹2,777\"},\"custom_notes\":\"Offer ends in 12 hours\"}"}, {"role": "assistant", "content": "{\"english_copy\":\"Your Smart TV is waiting in your cart! Complete checkout at ₹0 downpayment and easy EMIs of ₹2,777/mo. Offer ends in 12 hours!\",\"hinglish_copy\":\"Aapka Smart TV cart mein intezar kar raha hai! ₹0 downpayment par checkout karein aur pay karein easy EMIs of ₹2,777/month. Offer sirf agle 12 ghante ke liye hai!\",\"cta_text\":\"Complete Order Now\"}"}]}

D. AWS Bedrock Training Command (Mumbai ap-south-1)

aws bedrock create-model-customization-job \
    --region ap-south-1 \
    --job-name "snapmint-crm-nova-v1" \
    --custom-model-name "snapmint-crm-copywriter-v1" \
    --role-arn "arn:aws:iam::123456789012:role/BedrockFineTuningRole" \
    --base-model-identifier "arn:aws:bedrock:ap-south-1::foundation-model/amazon.nova-pro-v1:0" \
    --customization-type "FINE_TUNING" \
    --training-data-config '{"s3Uri": "s3://snapmint-bedrock-mumbai/data/train.jsonl"}' \
    --output-data-config '{"s3Uri": "s3://snapmint-bedrock-mumbai/output/"}'

6. Phase 1 Requirements (A to Z Checklist)

  • Frontend: React 19 + TypeScript + TailwindCSS portal hosted on S3 and CloudFront.
  • Backend: Python 3.12 + FastAPI async server running on AWS ECS Fargate in Mumbai VPC.
  • Database: Amazon Aurora PostgreSQL Serverless v2 for campaign briefs, versioning, and audit events.
  • AI Models: AWS Bedrock model access granted for Claude Sonnet 5 via India Geographic Profile.
  • Creative Renderer: Docker container running Headless Chromium + Playwright in Mumbai VPC.
  • Storage: S3 bucket with KMS Customer-Managed Key (CMK) for rendered creative PNGs.
  • Content Library Seed: CSV export of top 200 best-performing historical Snapmint campaigns.
