Phase 1 delivers the operational backbone of the Snapmint CRM platform over a 6-week delivery milestone (Weeks 4 to 10). It eliminates manual spreadsheet copywriting, unverified creative requests, and disconnected portal checks with a unified web application.

FINAL OUTCOME BY WEEK 10: A marketer fills a 1-minute brief in the portal (Product, Segment, Event, Channel, CTA, and Custom Comments). Campaign preparation turnaround drops from 24-48 hours to <5 minutes.

2. End-to-End Hop-by-Hop Request Flow

The exact journey of every campaign request from client submission to final launch:

  • 1. Marketer Form Submit: React Portal sends HTTPS POST request to FastAPI backend on AWS ECS Fargate in Mumbai VPC.
  • 2. Context & RAG Query: FastAPI queries Aurora PostgreSQL for 2-3 pre-approved high-converting past campaign examples for that product line.
  • 3. Bedrock Call (ap-south-1): FastAPI invokes Claude Sonnet 5 via India Geographic Profile (in.anthropic.claude-sonnet-5). Compute routes between Mumbai and Hyderabad with Zero Data Retention, returning copy variants and Layout JSON.
  • 4. Headless Chromium Render: FastAPI passes Layout JSON to Headless Chromium container in Mumbai VPC. Renders 1080x1080 PNG in <400ms and uploads to S3 with KMS encryption.
  • 5. WhatsApp Route Mobile API: Submits template payload to Route Mobile via POST /wba/template/create (Bearer JWT). Webhook listener receives real-time approval status from Meta.
  • 6. SMS DLT Whitelist Match: Computes SHA-256 hash of copy and checks local Aurora DLT Whitelist Ledger (manually seeded with Vilpower approved IDs). If matched, passes instantly. If new, generates Vilpower package for operator to register with POC OTP.
  • 7. Review Workspace & Launch Gate: Renders unified review screen. Authorized human manager clicks final Launch button.

3. Building the Campaign Portal: The Central Backbone

The brief form provides 5 core input controls designed to eliminate back-and-forth communication:

  • 1. Product Line (Dropdown): 0% EMI BNPL Checkout (Mobiles/Electronics), Personal Loan / Cash on EMI, Merchant Partner Flash Deals (OnePlus, Boat, Noise), or EMI Repayment Reminders.
  • 2. Audience Segment & Trigger Event (Dropdown): Encodes customer profile and behavioral trigger event:
    • Cart Abandoner: User added item to cart and completed OTP, but dropped off at payment.
    • Approved Zero Utilization: Granted ₹15,000 credit limit, but has not transacted in 14 days.
    • Repeat Limit Upgrade: Paid 2+ EMIs on time; eligible for upgrade to ₹40,000.
    • Dormant 90 Days: Inactive for 90+ days; cashback re-activation hook.
    • Near-Due 48 Hours: Installment due in 48 hours; instant UPI link.
  • 3. Communication Channel (Selector): WhatsApp Business message, SMS, or Mobile Push.
  • 4. Target CTA URL: Base destination URL. The portal automatically appends verified UTM tracking tags.
  • 5. Custom Comments / Special Instructions Box (Multi-line Textarea): Marketers can add specific nuances without altering system prompts (e.g. "Highlight flat ₹500 instant cashback on Axis Bank cards" or "Make tone urgent: flash deal ends tonight at 12 midnight").

4. WhatsApp Service Provider (WSP) API Feasibility & Real-Time Status Tracking

Can we check template category real-time and update the status in our portal? YES.

  • Route Mobile API: Programmatic template submission via POST https://apis.rmlconnect.net/wba/template/create using Bearer JWT authentication (via /login). Submits category, components, variable examples, and buttons.
  • Infobip API: Supported via POST /whatsapp/2/senders/{sender}/templates using API key.
  • Gupshup Reality: Public developer API only supports sending messages and listing templates. Fresh creation requires Enterprise Partner API or manual dashboard.
  • Real-Time Webhook Synchronization: Meta sends a message_template_status_update webhook event (APPROVED, REJECTED, FLAGGED, PAUSED, CATEGORY_CHANGED) directly to our AWS API Gateway endpoint. A Lambda worker updates the PostgreSQL template table, and Server-Sent Events (SSE) push the update to the React portal, updating the status badge in real time!

5. Telecom DLT (Vilpower) SMS Whitelisting Reality

TRAI DLT & POC OTP CONSTRAINT: As per TRAI regulations, telecom DLT platforms (Vilpower, Jio, Airtel) require human web portal logins with SMS OTP sent to the registered mobile number of Snapmint's authorized POC + CAPTCHA. AI agents CANNOT automate DLT login or bypass OTP. We solve this by manually adding approved DLT IDs and message bodies into our portal.

How the Portal DLT Whitelist Manager Works in Practice:

  • 1. Existing Templates (Day 1): Snapmint’s hundreds of approved Vilpower templates are exported to CSV and seeded into Aurora PostgreSQL. Any campaign matching these templates passes in 0 seconds.
  • 2. Generating New Templates: If new copy is generated that is not in the database, the portal outputs a One-Click Vilpower Registration Package (Header ID SNPMNT, Template Name, Text with {#var#}).
  • 3. Manual Operator Registration: The operator contacts the POC for the SMS OTP, logs into Vilpower, and registers the template.
  • 4. Manual Whitelist Entry in Portal: Once approved on Vilpower, the operator opens the portal's "DLT Whitelist Manager", pastes the approved 19-digit DLT Template ID and the exact approved message text, and clicks "Save to Whitelist".
  • 5. Instant Campaign Triggering: The portal computes the SHA-256 hash of the approved text. When triggering campaigns, the portal deterministically attaches the valid DLT Template ID and Header ID, guaranteeing that carrier scrubbing gateways will never drop the SMS.

6. Data Collection & Model Training Feasibility in Mumbai

Did we want to train the model with our old datasets across product lines and events? Is it feasible in Mumbai?

  • Claude Training is NOT Supported in Mumbai: AWS Bedrock does not support fine-tuning Claude inside ap-south-1. It is restricted to US regions, which violates Indian data residency.
  • Amazon Nova Supports Fine-Tuning in Mumbai: Supervised Fine-Tuning is supported natively for Amazon Nova Pro/Lite inside ap-south-1.
  • Why Fine-Tuning in Phase 1 is a Trap: Catastrophic forgetting when EMI rates change; high provisioned throughput costs; brittleness. In-Context Few-Shot Learning (RAG) with Claude Sonnet 5 gives 95%+ accuracy on Day 1 with ZERO training cost.
  • If Leadership Wants to Train in Mumbai: Extract 2,500-5,000 records from Databricks (CTR > 3%, Conv > 2%) + WebEngage + Vilpower. Scrub all PII. Format as Bedrock JSONL. Launch training job via AWS CLI: aws bedrock create-model-customization-job.
